Pull requests zijn welkom, van een typfout tot een nieuwe tool. Deze pagina is het pad om te
volgen; [Ontwikkeling](/avenir-mcp/nl/project/development/) beschrijft de repository en zijn
controles in detail. Je hebt een GitHub-account nodig, [git](https://git-scm.com),
[uv](https://docs.astral.sh/uv/) en [just](https://just.systems).

<Aside type="tip" title="Eerst overleggen, dan coderen">
Voor alles wat meer is dan een typefout of een zin in de documentatie, dient u eerst een
issue te openen of daarop te reageren — een [functieverzoek](/avenir-mcp/project/propose-a-feature/) of een
[bugrapport](https://github.com/mathbeal/avenir-mcp/issues/new?template=bug_report.yml) — en aan te geven dat u dit graag wilt uitvoeren.
Door vooraf overeenstemming te bereiken over de aanpak, voorkomt u dat u de code later opnieuw moet schrijven.
</Aside>

## Stap voor stap

<Steps>

1. **Forken en klonen.** Klik op GitHub op **Fork** en kloon vervolgens uw kopie. Met de
   [GitHub CLI](https://cli.github.com), in één opdracht:

   ```bash
   gh repo fork mathbeal/avenir-mcp --clone
   cd avenir-mcp
   ```

2. **Installeren en het vertrekpunt controleren.**

   ```bash
   uv sync       # Python 3.14 en de vastgelegde ontwikkeltools
   just check    # alles moet slagen voordat u iets verandert
   ```

3. **Maak een branch** met de naam van de wijziging:

   ```bash
   git switch -c feat/subscription-increases
   ```

4. **Schrijf eerst de test**, kijk hoe deze mislukt en schrijf vervolgens de code waarmee de test slaagt.
   Tests maken uitsluitend gebruik van verzonnen gegevens — nooit YNAB, nooit uw plan. Voeg gegevens toe aan het demoplan
   indien`evals/demo_budget.py` een voorbeeld nieuwe cijfers vereist.

5. **Draai de controles** tot ze allemaal slagen:

   ```bash
   just fix       # opmaak
   just check     # ruff, pylint, mypy, pytest (100 % dekking), woordenschat, lock
   just hygiene   # typos, controle van de workflows, licenties (REUSE)
   just secrets   # gitleaks op elke commit (vraagt Docker)
   ```

6. **Werk de documentatie bij.** Als een tool, de argumenten ervan of de resultaten zijn gewijzigd, voer
   `uv run python -m docsgen` de tool dan uit en leg de gegenereerde tekst vast. Een handmatig geschreven pagina wordt
   in alle talen van de website tegelijk gewijzigd;  de website wordt opnieuw `just docs`opgebouwd en
   er treedt een fout op bij een gebroken link.

7. **Commit** met een voorvoegsel dat het soort wijziging noemt – de changelog wordt eruit
   gegenereerd:

   ```bash
   git commit -s -m "feat: list subscriptions whose price went up"
   ```

   `-s` ondertekent de commit: u verklaart dat u in het bezit bent van het
   [Ontwikkelaarscertificaat van herkomst](https://developercertificate.org) — u hebt de
   wijziging geschreven of beschikt over het recht om deze in te dienen onder de MIT-licentie.

8. **Pushen en het pull request openen.**

   ```bash
   git push -u origin feat/subscription-increases
   gh pr create --fill
   ```

   Of open het via de link die GitHub toont. Vul het sjabloon in: wat en waarom, hoe het is
   gecontroleerd, de checklist, en `Closes #<issue>`.

</Steps>

## Wat er daarna gebeurt

| Fase | Wat u kunt verwachten |
|---|---|
| CI | dezelfde controles als  `just check`en `just hygiene`, op Linux, macOS en Windows, de documentatiebouw, de MCP Inspector, goedgekeurde commits en een titel die begint met het soort wijziging; **CI geslaagd** en **MCP Inspector** moeten groen zijn. Bij een eerste bijdrage keurt een beheerder de run eerst goed. |
| Beoordeling | opmerkingen over de code; push nieuwe commits naar dezelfde branch om hierop te reageren |
| Samenvoegen | samengevoegd tot één commit op `main`, met de titel van uw pull-verzoek als bericht |
| Uitgave | uw wijziging verschijnt in het [wijzigingslogboek](https://github.com/mathbeal/avenir-mcp/blob/main/CHANGELOG.md) | van de volgende versie |

## Wat een pull request mergeklaar maakt

- **Eén wijziging per pull request**, klein genoeg om in één keer te beoordelen.
- **Eerst tests geschreven**, die elke regel en vertakking dekken.
- **Geen nieuwe runtime-afhankelijkheid** zonder een reden in het pull request.
- **Schrijfacties blijven veilig**: een tool die het plan wijzigt, toont een voorbeeld,
  wacht op bevestiging en kan ongedaan worden gemaakt – zie
  [Veilig door ontwerp](/avenir-mcp/nl/concepts/safety/).
- **Geen echte financiële gegevens**, nergens: code, tests, documentatie, schermafbeeldingen.
- **Elke commit afgetekend** (`git commit -s`).

Het volledige contract staat in [AGENTS.md](https://github.com/mathbeal/avenir-mcp/blob/main/AGENTS.md),
dat geldt voor mensen en codeeragents.
