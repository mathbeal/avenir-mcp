avenir-mcp haalt zijn configuratie uit omgevingsvariabelen die zijn ingesteld in het `env`
blok van uw MCP-client of in de shell waarmee het programma wordt gestart. Er wordt verder niets gelezen: er is geen configuratiebestand.

## Overzicht

| Variabele | Standaardwaarde | Betekenis |
|---|---|---|
|  `YNAB_API_KEY`| — (**verplicht**, of `YNAB_API_KEY_FILE`) | Uw persoonlijke YNAB-toegangstoken. |
|  `YNAB_API_KEY_FILE`| niet ingesteld | Een bestand waarin het token is opgeslagen, dat wordt gebruikt wanneer  niet is`YNAB_API_KEY` ingesteld. |
|  `AVENIR_MCP_WRITE`| niet ingesteld: alleen-lezen |  `1`registreert de tools die uw plan wijzigen. |
|  `AVENIR_MCP_REQUIRE_ELICITATION`| niet ingesteld |  `1`accepteert alleen een ‘ja’ dat in de client wordt opgegeven: geen bevestigingscodes. |
|  `AVENIR_MCP_TRANSPORT`|  `stdio`|  `stdio`of `http`. |
|  `AVENIR_MCP_HOST`|  `127.0.0.1`| HTTP-adres. |
|  `AVENIR_MCP_PORT`|  `8103`| HTTP-poort. |
|  `AVENIR_MCP_HTTP_TOKEN`| niet ingesteld | Token dat HTTP-clients moeten overleggen; indien niet ingesteld, wordt bij elke start een willekeurig token gegenereerd. |
|  `AVENIR_MCP_JOURNAL`| zie hieronder | Journaalbestand, gebruikt voor het ongedaan maken van acties. |
|  `XDG_STATE_HOME`|  `~/.local/state`| De standaardlocatie van het journaal. |
|  `AVENIR_MCP_CONFIDENCE_THRESHOLD`|  `0.90`| Vereiste betrouwbaarheid om een categorie voor te stellen. |
|  `AVENIR_MCP_LOG_LEVEL`|  `WARNING`| Diagnostisch niveau. |
|  `AVENIR_MCP_LOG_FORMAT`|  `text`|  schrijft`json` één JSON-object per regel. |
|  `AVENIR_MCP_NO_UPDATE_CHECK`| niet ingesteld |  `1`stopt de dagelijkse controle op een nieuwere release op PyPI. |
|  `AVENIR_MCP_YNAB_URL`|  `https://api.ynab.com/v1`| API-adres. |

## Details

### `YNAB_API_KEY`

Je personal access token, uit YNAB → Account Settings → Developer Settings. Zonder token
faalt elke tool die YNAB aanroept met `YNAB_API_KEY environment variable is not set`. Het
geeft volledige lees- en schrijftoegang tot elk plan van het account.

### `YNAB_API_KEY_FILE`

Het pad naar een bestand dat uitsluitend het token bevat, dat wordt gebruikt wanneer  niet `YNAB_API_KEY`is ingesteld: het
token verschijnt dan in geen enkele MCP-clientconfiguratie. Het bestand mag alleen door u zelf kunnen worden gelezen
(`chmod 600`); anders weigert avenir-mcp het en geeft het een foutmelding. Op macOS, na het kopiëren van het token:

```bash
mkdir -p ~/.config/avenir-mcp
(umask 077; pbpaste > ~/.config/avenir-mcp/ynab-token)   # het token dat u net kopieerde
```

Geef `YNAB_API_KEY_FILE` dan het volledige pad van het bestand in het blok `env` van de
client.

Op macOS maakt de **sleutelhanger** een bestand helemaal overbodig: sla het token één keer
op en laat de client het bij het starten lezen.

```bash
security add-generic-password -a "$USER" -s avenir-ynab -w   # vraagt verborgen om het token
```

```json
"command": "/bin/sh",
"args": ["-c", "YNAB_API_KEY=$(security find-generic-password -s avenir-ynab -w) exec uvx avenir-mcp"]
```

macOS vraagt misschien één keer of `security` het item mag lezen.

### `AVENIR_MCP_WRITE`

Precies `1` registreert de 14 schrijftools. Elke andere waarde, of geen, houdt de server
alleen lezend: die tools worden dan niet getoond en zijn niet aan te roepen. Wordt één keer
gelezen, bij het opstarten.

### `AVENIR_MCP_REQUIRE_ELICITATION`

Precies`1`: een schrijfbewerking wordt pas uitgevoerd nadat de gebruiker in het eigen
bevestigingsvenster van de client ‘ja’ heeft gezegd. Er worden geen bevestigingscodes verstrekt of geaccepteerd; een gesloten
vraag geldt als ‘nee’, en een client die geen vraag kan stellen, krijgt een foutmelding. Gebruik dit wanneer het model
mogelijk een code doorgeeft zonder u hierom te vragen — zie
[Bevestiging](/avenir-mcp/concepts/confirmation/#requiring-the-users-own-answer).

### `AVENIR_MCP_TRANSPORT`, `AVENIR_MCP_HOST`, `AVENIR_MCP_PORT`

`stdio` (standaard) voor een client die de server zelf start. `http` biedt streamable HTTP
aan op `http://{HOST}:{PORT}/mcp`.

```bash
AVENIR_MCP_TRANSPORT=http AVENIR_MCP_PORT=9000 YNAB_API_KEY=… uvx avenir-mcp
```

<Aside type="danger">
Het verkeer is gewoon HTTP: houd `AVENIR_MCP_HOST` op `127.0.0.1`. `HOST` en `PORT` zonder
voorvoegsel worden bewust genegeerd: shells zetten `HOST` vaak op de naam van de computer.
</Aside>

### `AVENIR_MCP_HTTP_TOKEN`

Via HTTP een geheim dat elk verzoek moet dragen als `Authorization: Bearer <token>`; andere
krijgen `401`. **Via HTTP altijd verplicht**: is het niet ingesteld, dan maakt de server bij
elke start een willekeurig token en toont het één keer op stderr. Maak er een aan met `openssl rand -hex 32`. Genegeerd via stdio. Welk token ook,
de headers `Host` en `Origin` moeten deze computer noemen. Zie
[Via HTTP draaien](/avenir-mcp/nl/guides/run-options/#via-http-draaien).

### `AVENIR_MCP_JOURNAL` en `XDG_STATE_HOME`

Het journaal van toegepaste operaties. Standaard: `$XDG_STATE_HOME/avenir-mcp/journal.jsonl`,
of `~/.local/state/avenir-mcp/journal.jsonl` als `XDG_STATE_HOME` niet is ingesteld. De map
wordt aangemaakt als dat nodig is. Zie
[Journaal en ongedaan maken](/avenir-mcp/nl/concepts/journal/).

### `AVENIR_MCP_CONFIDENCE_THRESHOLD`

Een getal tussen 0 en 1: het deel van de geschiedenis van een begunstigde dat moet
overeenkomen voordat een categorie wordt voorgesteld. `0.90` stelt minder vaak voor en zit
vaker goed; `0.70` stelt meer voor. Wordt bij het opstarten gelezen. Zie
[Suggesties](/avenir-mcp/nl/concepts/suggestions/).

### `AVENIR_MCP_LOG_LEVEL`

`DEBUG`, `INFO`, `WARNING` (standaard), `ERROR`. Diagnoses gaan naar stderr. Op `INFO`
wordt elke toolaanroep en elk YNAB-verzoek gelogd – alleen id's en aantallen, nooit
begunstigden, bedragen of namen; het token nooit. `DEBUG` voegt de eigen meldingen van de
MCP-bibliotheek toe, die de verzoeken zelf kunnen bevatten.

### `AVENIR_MCP_LOG_FORMAT`

`text` (standaard): één leesbare regel per gebeurtenis. `json`: één JSON-object per regel,
voor een logcollector – zie
[Logs naar een logsysteem sturen](/avenir-mcp/nl/guides/run-options/#logs-naar-een-logsysteem-sturen).

### `AVENIR_MCP_NO_UPDATE_CHECK`

Niet ingesteld (standaard): bij het opstarten, maximaal één keer per dag, vraagt de server PyPI
(`https://pypi.org/pypi/avenir-mcp/json`
) om de nieuwste release, waarbij hij maximaal 1,5 seconde wacht,
en onthoudt het antwoord in  `latest-version.json`
onder `XDG_CACHE_HOME`
(`~/.cache`
standaard). Wanneer er een nieuwere release beschikbaar is, wordt via een regel in de instructies van de server
een melding naar de agent gestuurd, die u hiervan op de hoogte kan stellen, en wordt dezelfde regel als waarschuwing geregistreerd. Er wordt niets over u of uw plannen verzonden: het betreft één
anoniem verzoek, dat door PyPI wordt gezien als afkomstig van uw adres. De server voert nooit zelf een upgrade uit
. `1`
: helemaal geen verzoek; `DO_NOT_TRACK=1`
, of een CI-run (`CI=true`
), heeft hetzelfde effect.

### `AVENIR_MCP_YNAB_URL`

Het basisadres van de API. Dit is alleen nuttig om avenir-mcp naar een stand-in te verwijzen, zoals de evaluatie en
de documentatiegenerator dat doen met hun demo-planserver. Het moet beginnen met
`https://` — ‘plain’ `http://`wordt alleen geaccepteerd voor  `127.0.0.1`of  `localhost`— omdat
elk verzoek uw token bevat.

## Argumenten van hulpprogramma’s die u vaak zult tegenkomen

| Argument | Geaccepteerde waarden |
|---|---|
| `plan_id` | een plan-id uit `list_plans`, of `last-used` |
| `month` | `current`, of de eerste dag van een maand: `YYYY-MM-01` |
| `until` | een maand, `YYYY-MM`, tot 24 maanden vooruit |
| data | `YYYY-MM-DD` |
| bedragen | valuta-eenheden; negatief voor uitgaven |
