## Limites connues

| Domaine | Limite | Contournement |
|---|---|---|
| Codes de confirmation | gardés en mémoire : un redémarrage du serveur les oublie | redemander un aperçu |
| Annulation | locale à la machine dont le journal a enregistré l'opération ; une annulation ne s'annule pas | refaire le changement |
| `approve_transactions` | s'applique aussitôt, sans aperçu | il ne lève que le marqueur de revue de YNAB |
| `import_transactions` | s'applique aussitôt, sans aperçu ; non annulable ici | il n'apporte que ce que la banque a déjà ; supprimer une transaction dans YNAB pour revenir en arrière |
| `update_category`, `create_category` | non annulables ; l'API YNAB ne peut pas supprimer une catégorie | renommer à nouveau ; masquer la catégorie dans YNAB |
| Transport HTTP | HTTP simple, un seul jeton partagé, pas de comptes | le garder sur `127.0.0.1`, ou utiliser stdio |
| Serveur public ou partagé | non pris en charge : pas de comptes, et les conditions de YNAB imposent OAuth pour les plans d'autrui | chacun fait tourner son propre avenir-mcp — voir les [mentions légales](/avenir-mcp/fr/project/legal/) |
| Transactions ventilées | jamais proposées ni recatégorisées : leurs lignes portent les catégories ; `split_transaction` en ventile une, mais l'API YNAB ne peut ni modifier ni annuler une ventilation | les modifier ou les annuler dans YNAB |
| Suggestions | exigent un historique : un commerçant jamais classé n'en reçoit pas | l'agent propose, vous décidez |
| Prévision | prolonge les derniers mois, plus les transactions planifiées de YNAB ; une charge trimestrielle ou annuelle sans échéance n'est pas récurrente à ses yeux | la planifier dans YNAB, ou la passer en `one_offs` |
| Devise | montants affichés en nombres, sans symbole monétaire | — |
| Python | 3.12 à 3.14 ; 3.15 attend une dépendance (beartype) | — |

## Feuille de route

- D'un document aux échéances de l'année : l'agent lit un avis d'impôt ou un appel de fonds, et avenir-mcp crée ou met à jour les échéances et les objectifs qu'il fixe, en un seul lot prévisualisé, confirmé et annulable.
- Les abonnements et prélèvements récurrents, en lecture seule : ce que vous payez chaque mois ou chaque année, et ce que cela a coûté.
- Les bénéficiaires : les lister, et renommer un libellé bancaire en nom du commerçant, avec aperçu et annulation.
- Modifier une transaction (date, montant, bénéficiaire, mémo), une fois décidé si le journal local peut garder l'ancien mémo, ce qui permettrait de l'annuler.
- Un paquet `.mcpb` pour une installation en un clic dans Claude Desktop.
- L'annulation pour `update_category`.
- Abaisser la version minimale de Python dès que les dépendances le permettent.
- Lancer l'évaluation avec d'autres clients que Claude Code, et avec des modèles locaux.
