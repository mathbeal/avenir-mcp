---
title: Dépannage
description: Problèmes fréquents et leurs solutions.
---

<details>
<summary>Mon client n'affiche pas les outils d'Avenir</summary>

- Vérifiez que le serveur est connecté : `claude mcp list`, ou le panneau MCP de votre client.
- Lancez `uvx avenir-mcp` dans un terminal : il doit attendre un client en silence. Une
  erreur à cet endroit est celle que votre client vous cache.
- Redémarrez le client après avoir modifié sa configuration.

</details>

<details>
<summary>Les outils qui modifient mon budget manquent</summary>

Avenir est en lecture seule tant que `AVENIR_MCP_WRITE=1` n'est pas dans son environnement.

</details>

<details>
<summary><code>YNAB 401</code></summary>

Le jeton est faux ou révoqué. Créez-en un nouveau dans les Developer Settings de YNAB.

</details>

<details>
<summary><code>YNAB 429</code></summary>

YNAB autorise 200 requêtes par heure et par jeton. Attendez quelques minutes ; la
synchronisation incrémentale d'Avenir rend les appels suivants peu coûteux.

</details>

<details>
<summary>L'agent répète <code>confirmation_required</code></summary>

Votre client ne sait pas afficher de case de confirmation : Avenir a renvoyé un aperçu et
un code. Dites à l'agent que vous êtes d'accord : il rappelle l'outil avec le code. Un
code dure 10 minutes et ne sert qu'une fois.

</details>

<details>
<summary><code>ModuleNotFoundError: avenir_mcp</code> dans un dossier synchronisé par iCloud Drive</summary>

iCloud peut marquer des fichiers comme cachés, et les versions récentes de Python
ignorent les fichiers `.pth` cachés, ce qui casse les installations éditables. Gardez
l'environnement virtuel hors du dossier synchronisé :
`UV_PROJECT_ENVIRONMENT=~/.local/share/avenir-mcp/venv uv sync`.

</details>

<details>
<summary>Où voir ce que fait le serveur ?</summary>

Réglez `AVENIR_MCP_LOG_LEVEL=DEBUG`. Les diagnostics vont sur stderr, que votre client
conserve en général dans ses journaux MCP ; stdout appartient au protocole.

</details>
