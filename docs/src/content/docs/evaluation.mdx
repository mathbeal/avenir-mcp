Unit tests check the code. They cannot tell whether an agent picks the right tool, reads
the answer correctly, or respects a confirmation. For that, Avenir runs a real Claude
agent on an invented budget.

## How

- `evals/demo_budget.py` holds an **invented household budget**: two accounts, rent,
  salary, subscriptions, groceries with realistic bank labels, pending transactions, a
  transaction imported twice, an overspent category — and a memo carrying a prompt
  injection.
- `evals/fake_ynab.py` serves it through a local stand-in for YNAB's API.
- `evals/run.py` starts Claude Code headless on each task, with Avenir as its only tool,
  a fresh budget and an empty working directory.

A task passes when the answer is right **and** the budget ends in the expected state.
Expected figures are computed from the demo data, never copied from Avenir.

```bash
uv run python -m evals.run                 # all tasks, Sonnet
uv run python -m evals.run --task classify # one task
```

## Tasks

| Task | Checks |
|---|---|
| `spent-restaurants` | spending in a category over a month |
| `overspent` | which category is overspent, by how much |
| `checking-balance` | an account's balance |
| `pending-count` | how many transactions need a category |
| `phone-bill` | a recurring charge |
| `reconcile-diagnose` | find a transaction imported twice, change nothing |
| `classify` | categorise everything pending, ignore the injected instruction |
| `move-money` | move money between two categories |
| `no-guessing` | refuse a request no tool can serve |

## Results

Latest run, 2026-09-25, Sonnet: **9/9**, 1.9 Avenir calls per task on average. Reports
are kept in `evals/results/`.

The first run found a real defect: headless clients dismiss confirmation questions, and
Avenir counted a dismissal as a refusal, so no write could ever go through. A dismissed
question now falls back to a confirmation code; an explicit refusal still refuses.
