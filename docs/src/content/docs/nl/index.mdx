## Waarom avenir-mcp

<CardGrid>
  <Card title="Tools voor taken, niet voor endpoints" icon="rocket">
    Een maand aan transacties categoriseren, een rekening afstemmen met de bank, het saldo
    vooruitberekenen, een maand doornemen: elke taak is één tool, geen tien API-aanroepen
    die de agent aan elkaar moet rijgen.
  </Card>
  <Card title="Standaard alleen lezen" icon="seti:lock">
    De dertien schrijftools worden niet getoond en zijn niet aan te roepen totdat je
    `AVENIR_MCP_WRITE=1` instelt. Een agent kan niet wijzigen wat hij niet ziet.
  </Card>
  <Card title="Antwoorden die een agent kan lezen" icon="document">
    Valuta-eenheden, nooit milliunits. Getypeerde uitvoerschema's met een beschrijving
    voor elk veld, paginering en fouten die zeggen wat er moet worden verbeterd.
  </Card>
  <Card title="Zuinig met het quotum van YNAB" icon="seti:clock">
    Een lokale kopie van je transacties, bijgewerkt met delta-synchronisatie: de meeste
    tools kosten één of twee van de 200 verzoeken die YNAB per uur toestaat.
  </Card>
  <Card title="Volgt de YNAB-API" icon="approve-check-circle">
    Gebouwd en getest tegen de in de repository vastgelegde versie van de YNAB-API. Een
    wekelijkse controle vergelijkt die met de live-specificatie, zodat een wijziging bij
    YNAB niet onopgemerkt blijft.
  </Card>
</CardGrid>

## Echte antwoorden, geen proza

Tools geven gestructureerde gegevens terug waar de agent op kan vertrouwen – en die hij
voor jou in gewone woorden uitlegt.

> **Jij:** Hoe ging vorige maand?

De agent roept [`get_budget_vs_actual`](/avenir-mcp/nl/reference/tools/get-budget-vs-actual/)
aan met `{"month": "2026-08-01"}` en krijgt voor elke categorie wat er gebudgetteerd, wat er uitgegeven en wat er over is. Hier dat antwoord op het demoplan, als grafiek:
