Cada escritura confirmada se anota en un diario local, para que `undo_operation` pueda
deshacerla más tarde — incluso tras reiniciar el servidor.

## Dónde

| | |
|---|---|
| Archivo por defecto | `$XDG_STATE_HOME/avenir-mcp/journal.jsonl`, si no `~/.local/state/avenir-mcp/journal.jsonl` |
| Archivo elegido | `AVENIR_MCP_JOURNAL` |
| Permisos | creado en `0600`: solo usted puede leerlo y modificarlo |
| Contenido | identificadores y, para un cambio de presupuesto, los importes asignados antes y después — ni importes de transacciones, ni beneficiarios, ni memos, ni token |

## Formato

JSON Lines, en modo de solo anexado. Una operación aplicada ocupa una línea:

```json
{"operation_id":"5f2c9a1e7b30","plan_id":"demo-budget","kind":"categorize","applied_at":"2026-09-25T09:12:04+00:00","moves":[{"transaction_id":"tx-048","from_category_id":null,"to_category_id":"cat-groceries"}],"details":{}}
```

Deshacerla añade un marcador; nunca se reescribe nada:

```json
{"undone":"5f2c9a1e7b30"}
```

| Campo | Significado |
|---|---|
| `operation_id` | 12 caracteres hexadecimales aleatorios |
| `plan_id` | el plan modificado |
| `kind` | `categorize`, `budget`, `move`, `reconcile` o `create` |
| `applied_at` | ISO 8601, UTC, al segundo |
| `moves` | para `categorize`: la categoría de cada transacción antes y después |
| `details` | para los demás tipos, lo que necesita la anulación (abajo) |

| `kind` | `details` |
|---|---|
| `budget` | `month`, `category_id`, `from` y `to` en miliunidades |
| `move` | `month`, y `changes`: para cada una de las dos categorías, `category_id`, `from` y `to` en miliunidades |
| `reconcile` | `account_id`, `reconciled_ids`, `adjustment_id` (o `null`) |
| `create` | `transaction_ids` |

## Qué operación se deshace

Sin id, `undo_operation` toma **la operación más reciente del plan aún vigente**:
que no se haya deshecho ni sea a su vez una anulación. Con un id, esa operación, si sigue
vigente. Si no: *«Nothing to undo: no operation of this plan is still in effect.»*

## Qué restaura la anulación

| `kind` | Deshacer | Se comprueba antes | Si la comprobación falla |
|---|---|---|---|
| `categorize` | cada transacción recupera su categoría anterior | su categoría sigue siendo la que puso la operación | esa transacción se deja igual y se lista en `conflicts` |
| `budget` | el importe anterior | el importe sigue siendo el que puso la operación | nada escrito; `conflicts` nombra la categoría |
| `move` | los dos importes anteriores | los dos importes siguen siendo los que puso la operación | nada escrito; `conflicts` nombra la categoría que cambió |
| `reconcile` | las transacciones *reconciled* vuelven a *cleared*; se borra el ajuste | cada una sigue *reconciled* | las que ya no lo están se omiten |
| `create` | se borran las transacciones creadas | cada una sigue existiendo | las ya borradas se listan en `conflicts` |

La anulación se previsualiza y confirma como cualquier escritura. Deshacer una operación
`categorize` registra la anulación como una operación y marca ambas como deshechas: una anulación no se puede deshacer.

<Aside type="note">
El diario es local: una operación hecha desde otra máquina, o antes de que el archivo del
diario cambiara o se borrara, no se puede deshacer desde aquí. Borrar el archivo borra el
historial, y nada más.
</Aside>
