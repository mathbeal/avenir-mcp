**Doel:** een wijziging die via avenir-mcp is gedaan terugdraaien.

**Tool:** [`undo_operation`](/avenir-mcp/nl/reference/tools/undo-operation/).

## Het gesprek

<Steps>

1. **Vraag het.**

   > **Jij:** Maak dat ongedaan.

2. **De agent toont het ongedaan maken als voorbeeld.** `undo_operation` met
   `{"plan_id": "last-used"}` vindt de laatste operatie van het plan die nog van kracht
   is, en laat zien wat ongedaan maken zou veranderen – hier twee transacties die weer geen
   categorie hebben:

   <Code code={undo} lang="json" title="undo_operation — voorbeeld" />

3. **Je bevestigt.** De vorige toestand wordt hersteld, en de operatie wordt in het
   journaal als ongedaan gemarkeerd.

</Steps>

Om een eerdere bewerking ongedaan te maken, geeft u de bijbehorende id op: *„bewerking 3f9a ongedaan maken…“*. Het resultaat van elke toegepaste
bewerking bevat de bijbehorende `operation_id`.

## Wat ongedaan kan worden gemaakt

| Operatie | Ongedaan maken herstelt | Blijft ongemoeid als |
|---|---|---|
| `apply_categories` | de vorige categorie van elke transactie | haar categorie sindsdien opnieuw is veranderd |
| `set_category_budget` | het vorige bedrag | het bedrag sindsdien opnieuw is veranderd |
| `move_money` | beide vorige bedragen | een van beide bedragen sindsdien opnieuw is veranderd (dan blijven beide ongemoeid) |
| `flag_transactions` | de vorige vlag van elke transactie | de vlag sindsdien opnieuw is veranderd |
| `rename_payee` | de vorige naam van de begunstigde | die sindsdien opnieuw is hernoemd |
| `set_category_target` | het vorige doel | het doel sindsdien opnieuw is veranderd; een soort die de API van YNAB niet kan aanmaken (maandelijkse financiering, doelsaldo, schuldaflossing) is na vervangen of weghalen niet meer ongedaan te maken, zoals de vraag aankondigt |
| `reconcile_account` | de status *cleared*; verwijdert de correctie | een transactie niet meer afgestemd is |
| `create_transactions` | verwijdert de aangemaakte transacties | er een al verwijderd was |

Alles wat ongemoeid blijft, staat in `conflicts`: ongedaan maken overschrijft nooit later
werk.

**Niet ongedaan te maken:** `update_category` (roep het opnieuw aan met de vorige naam en
groep), `create_category` (verberg de categorie in YNAB), `split_transaction` (de API van
YNAB kan een splitsing niet wijzigen: bewerk haar in YNAB), `approve_transactions` (de
goedkeuring is een controlemarkering).

<Aside type="note">
Een ongedaanmaking kan zelf niet ongedaan worden gemaakt, en ongedaan maken werkt op de
computer waarvan het [journaal](/avenir-mcp/nl/concepts/journal/) de operatie heeft
vastgelegd.
</Aside>
