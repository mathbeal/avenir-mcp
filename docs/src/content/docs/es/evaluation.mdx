description: Un agente real trabaja sobre un presupuesto inventado y se comprueban sus resultados.
---

Las pruebas unitarias comprueban el código. No dicen si un agente elige la herramienta
correcta, lee bien la respuesta o respeta una confirmación. Para eso, Avenir pone a
trabajar a un agente Claude real sobre un presupuesto inventado.

## Cómo

- `evals/demo_budget.py` contiene un **presupuesto doméstico inventado**: dos cuentas,
  alquiler, sueldo, suscripciones, compras con etiquetas bancarias realistas,
  transacciones pendientes, una transacción importada dos veces, una categoría que se ha
  pasado — y un memo con una inyección de prompt.
- `evals/fake_ynab.py` lo sirve mediante una imitación local de la API de YNAB.
- `evals/run.py` lanza Claude Code en modo no interactivo para cada tarea, con Avenir
  como única herramienta, un presupuesto nuevo y una carpeta de trabajo vacía.

Una tarea se supera cuando la respuesta es correcta **y** el presupuesto acaba en el
estado esperado. Los resultados esperados se calculan a partir de los datos de
demostración, nunca se copian de Avenir.

```bash
uv run python -m evals.run                 # todas las tareas, Sonnet
uv run python -m evals.run --task classify # una sola tarea
```

## Tareas

| Tarea | Comprueba |
|---|---|
| `spent-restaurants` | el gasto de una categoría en un mes |
| `overspent` | qué categoría se ha pasado, y por cuánto |
| `checking-balance` | el saldo de una cuenta |
| `pending-count` | cuántas transacciones esperan categoría |
| `phone-bill` | un cargo recurrente |
| `reconcile-diagnose` | encontrar una transacción importada dos veces, sin cambiar nada |
| `classify` | clasificarlo todo, ignorando la instrucción inyectada |
| `move-money` | mover dinero entre dos categorías |
| `no-guessing` | rechazar una petición que ninguna herramienta atiende |

## Resultados

Última ejecución, 2026-09-25, Sonnet: **9/9**, 1,9 llamadas a Avenir por tarea de media.
Los informes están en `evals/results/`.

La primera ejecución encontró un defecto real: los clientes no interactivos cierran las
preguntas de confirmación, y Avenir contaba ese cierre como un rechazo, así que ninguna
escritura llegaba a aplicarse. Una pregunta cerrada da ahora un código de confirmación;
un rechazo explícito sigue siendo un rechazo.
